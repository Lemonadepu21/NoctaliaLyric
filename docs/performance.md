# 1.2.0 优化验证

日期：2026-10-21。Noctalia 5.3.0，一份歌词组件，SPlayer 暂停在相同位置，桌面处于锁屏状态。播放器播放状态与进度未被测试更改。

实现：共享 D-Bus 监听替代 500 ms 全量轮询；MPRIS 歌词按内容变化解析并缓存；缺少歌词直接显示歌曲信息；静态 UI 与重复 SVG 帧去重；左键原生媒体卡片、中键原生播放/暂停、右键设置。

## 结果

采用“开→关→关→开”四个约 10 秒资源窗口，切换后等待 3 秒。CPU 按单核 100% 计算。

| 指标 | 关闭 | 开启 |
| --- | ---: | ---: |
| Noctalia CPU | 1.04% | 1.09% |
| 已回收子进程 CPU | 0.00% | 0.00% |
| Noctalia RSS | 336.74 MiB | 338.03 MiB |
| Noctalia PSS | 244.56 MiB | 245.86 MiB |

另测常驻监听与等待 shell：10 秒内没有累计到可测的 CPU 时间，两者合计 PSS 约 2.11 MiB（RSS 含共享库，不能直接作为独占内存）。主进程约 0.05 个百分点的 CPU 差值处于这次短测的波动范围内，不代表插件完全没有开销。

各资源窗口之后另做 6 秒进程创建采样。两个开启窗口均未观察到新建查询进程；关闭窗口同样没有。启动时的列表/状态读取不在稳态采样中。播放时仍会按默认 30 秒间隔创建一次 Position 校准查询，暂停时不创建。

优化前审查观察到暂停时每 10 秒创建 20 个 playerctl；本次查询创建已经消除。优化前后桌面锁屏条件不同，所以不以两次总 CPU 数字直接计算百分比收益。

## 其他验证

- 139 项检查通过，配置有效，插件检查 0 错误、0 警告。
- 实机结束监听进程后，4 秒内恢复且仍只有一条监听。
- 实际 PropertiesChanged、Seeked 消息格式与解析器一致，其他 D-Bus owner 的信号会被忽略。
- 组件与栏的外观参数对比一致；已移除废弃的歌词来源配置，并保留修改前备份。
- 宿主确认左键 `panel-toggle control-center media`、中键 `media toggle`、右键 `settings-open-widget`。

## 限制

当前 SPlayer 没有通过 MPRIS 提供歌词，回退显示歌曲信息是预期行为。没有扫描 LRC、播放器 HTTP 或在线歌词请求。

未解锁桌面实际点按媒体卡片，未复测动画 CPU 峰值、GPU 占用和长时间内存趋势。滚动效果仍需要 SVG 图片帧更新，缓存降低重复工作，没有把它变成零成本原生文字动画。
